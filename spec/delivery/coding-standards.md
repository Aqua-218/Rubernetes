# 10. コーディング規約

> 対象読者: すべての実装者、レビュア
>
> 状態: 規範、版0.2

Ruby、FFI、エラー、並行性、不変性、メタプログラミング、形式仕様との対応についての規約を定義する。

<a id="sec-10-1"></a>
## 10.1 方針

各規則には根拠を付ける。根拠を書けない規則は採用しない。「一般に良いとされているから」は、根拠として認めない。

規則の厳しさは、層によって変える。低い層ほど、誤りの影響が広く及び、発見も遅れるためである。

| 層 | 厳しさ |
|---|---|
| FFI、ランタイム、ネットワークのうち、システムコールを直接呼ぶ部分 | 最大 |
| Raft、ストア | 高 |
| コントローラ、スケジューラ、agent | 標準 |
| CLI、テストの補助 | 緩い |

<a id="sec-10-2"></a>
## 10.2 分類

| 記号 | 意味 |
|---|---|
| **M** | 必須。逸脱を認めない |
| **R** | 要求。逸脱には記録（[§10.9](coding-standards.md#sec-10-9)）を要する |
| **A** | 推奨。逸脱は自由 |
| ⚙ | 機械判定可能。CI で強制する |
| 👁 | 機械判定不能。レビューで確認する |

<a id="sec-10-3"></a>
## 10.3 R-1 FFI と syscall

**R-1.1 M ⚙** すべての syscall 戻り値を検査する。
根拠: 失敗を見逃すと、カーネル側の状態が想定と乖離したまま処理が進み、
問題の発生箇所と原因箇所が大きく離れる。

**R-1.2 M ⚙** `errno` は syscall 直後に読む。
根拠: 後続の任意のライブラリ呼び出しが `errno` を上書きする。

**R-1.3 M 👁** 確保した資源（fd、mount、namespace、cgroup、VM）は、
取得前 intent、取得後 identity、解放状態を同一の ownership object と durable ledger で対にする。
異常終了後も [§5.8.4](../node/runtime.md#sec-5-8-4) の逆順で回収できること。
根拠: リークしたマウントや namespace はプロセス終了後も残り、
ホストを汚染して次回以降の起動を妨げる。

**R-1.4 M 👁** 定数（syscall 番号、フラグ、netlink の型）は出典を注記する。
根拠: 値の正しさをコードから判断できないため、
検証にはヘッダとの突き合わせが必要になる。

**R-1.5 R 👁** 構造体のレイアウトはアーキテクチャごとに定義し、
サイズをテストで検証する。
根拠: パディングとアラインメントの誤りは、
一見動作するが特定条件でのみ壊れる。

**R-1.6 M 👁** 順序に意味のある操作は、順序の理由をコメントに書く。
根拠: `no_new_privs` と seccomp のように、
順序を入れ替えると静かに無効化される組み合わせが存在する。

<a id="sec-10-4"></a>
## 10.4 R-2 エラー

**R-2.1 M ⚙** 例外を握りつぶさない。`rescue` の本体を空にしない。
根拠: 分散システムでは、飲み込まれたエラーが不整合として
別の場所に遅れて現れ、原因の特定が困難になる。

**R-2.2 M ⚙** `rescue` は捕捉する例外クラスを明示する。
`rescue => e` および `rescue Exception` を禁じる。
根拠: 制御用の例外や割り込みまで捕捉してしまう。

**R-2.3 R 👁** 同期的再試行は回数上限と待機戦略を明示する。
収束に必要な非同期再試行は最大 backoff、cancellation 条件、durable queue を明示する。
根拠: 無制御な再試行は障害時に負荷を増幅し、永久破棄は desired state への収束を壊す。

**R-2.4 R 👁** 回復不能な状態では速やかに落とす。
不整合な状態のまま処理を続けない。
根拠: 破損した状態での継続は、被害を回復不能な範囲に広げる。

<a id="sec-10-5"></a>
## 10.5 R-3 並行

**R-3.1 M 👁** 共有可変状態への参照は必ず同期機構を経る。
根拠: コントローラは並行に reconcile を実行するため、
非同期な読み書きは容易に発生する。

**R-3.2 R 👁** ロックの取得順序を文書化し、それに従う。
根拠: 順序の不一致がデッドロックの唯一の実効的な原因である。

**R-3.3 R ⚙** Thread の生成箇所を集約する。任意の場所で生成しない。
根拠: 生成箇所が分散すると、停止処理の網羅性を確認できない。

**R-3.4 M 👁** 同一 Pod に対する操作は直列化する。
根拠: 起動と削除が並行すると、
解放済み資源への操作が発生する。

<a id="sec-10-6"></a>
## 10.6 R-4 不変性

**R-4.1 M 👁** 内部表現のリソースオブジェクトは不変として扱う。
更新は複製して行う。
根拠: 共有キャッシュ上のオブジェクトを変更すると、
無関係なコントローラの判断が変わる。

**R-4.2 M ⚙** キャッシュから返すオブジェクトは freeze する。
根拠: R-4.1 を規約ではなく機構で保証するため。

**R-4.3 R 👁** 破壊的メソッド（`!` 付き、`<<` 等）は
自スコープで生成したオブジェクトにのみ用いる。
根拠: 同上。

<a id="sec-10-7"></a>
## 10.7 R-5 動的機能

**R-5.1 M ⚙** `eval`、`instance_eval` を文字列引数で用いない。
根拠: 静的解析が不能になり、規約の機械判定が成立しなくなる。

**R-5.2 M ⚙** 標準ライブラリおよび外部 gem のクラスを再定義しない。
根拠: 影響範囲がプロセス全体に及び、局所的な検証で捉えられない。

**R-5.3 R 👁** `define_method` による定義は、
schema compiler が生成する型、codec、manifest DSL、controller/scheduler の登録面に限る。
用いる場合は生成されるメソッド名を
一覧化できること。
根拠: API の型定義は宣言的に書くのが適切であり、
Ruby の利点でもある。一方で無制限に使うと
呼び出し可能なメソッドの全体像が把握できなくなる。

**R-5.4 R ⚙** `send` を用いて private メソッドを呼ばない。
根拠: カプセル化の境界が意味を失う。

**R-5.5 M ⚙** `method_missing` と `respond_to_missing?` を schema、GVK、field、plugin 解決に用いない。
根拠: typo が実行時まで検出されず、生成 API 全体を RBS と静的検査へ公開できなくなる。

**R-5.6 M 👁** user supplied Ruby DSL は cluster credential を持たない隔離 process で評価し、
明示的な信頼承認なしに実行しない。
根拠: Ruby DSL は設定データではなく任意コードであり、manifest の閲覧とコード実行を同一視できない。

<a id="sec-10-8"></a>
## 10.8 R-6 形式仕様との対応

**R-6.1 M 👁** TLA+ 仕様に対応する実装箇所には、
対応する動作名をコメントで示す。
根拠: 仕様と実装の対応が失われると、
検証結果が実装について何も保証しなくなる。

**R-6.2 M 👁** Lean で証明した性質に依存する実装箇所には、
定理名をコメントで示す。
根拠: 同上。加えて、実装変更時に
どの証明を再確認すべきかを判断できるようにする。

**R-6.3 R 👁** 仕様を変更した場合、
対応する実装とコメントを同一の変更単位で更新する。
根拠: 分離すると乖離が生じる。

<a id="sec-10-9"></a>
## 10.9 R-7 文書

**R-7.1 M 👁** コメントには「なぜ」を書く。「何を」は書かない。
根拠: 「何を」はコードから読める。重複した記述は
コード変更時に更新されず、誤った情報として残る。

**R-7.2 M 👁** 規約から逸脱する場合、逸脱記録を残す。
記録には、逸脱した規則番号、理由、影響範囲、
代替の安全確保手段を含める。
根拠: 逸脱そのものは避けられない。
避けるべきは、理由が失われた逸脱である。

**R-7.3 M ⚙** 規範仕様、schema、release artifact に未決マーカー、期限のない作業注記、
「実装時に決定」を残さない。
根拠: 未決のまま実装すると複数 component が異なる仮定を採用し、互換性を判定できなくなる。

<a id="sec-10-10"></a>
## 10.10 適用しない規則と理由

以下は検討した上で採用しない。

| 規則案 | 不採用の理由 |
|---|---|
| 1 メソッドの行数上限 | Ruby ではブロックにより行数が自然に伸びる。行数と理解容易性の相関が弱い |
| 循環的複雑度の上限 | 根拠が経験則に留まり、本プロジェクト固有の理由を示せない |
| 再帰の禁止 | 木構造（所有グラフ、OverlayFS 層）の処理で再帰が自然。深さは入力により有界 |
| 例外の全面禁止（Result 型） | 標準ライブラリが例外を投げるため境界で変換が必要になり、変換漏れという新たな誤りを生む |
| `nil` の禁止 | Kubernetes API は未設定と空を区別する。`nil` の排除は表現力を失う |
